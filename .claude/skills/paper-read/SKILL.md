# paper-read — 논문 읽고 정리하기

논문을 **토큰을 아껴서** 읽고, **저자 주장과 외부 평가를 분리해** 정리한다. 요약만 하면 저자 주장이 사실처럼
읽히기 때문에, 이 스킬의 가치는 "남들이 이 논문을 어떻게 봤나"를 출처 성격과 함께 붙이는 데 있다.

작업 위치: 저장소 루트 · 파이썬 3.11+ (`requirements.txt`)

시작할 때 `python -m paper_analyst.profile` 로 현재 프로필을 읽는다 — **출력 언어(`reader.language`)·읽는 관점(`reader.lens`)·관심 주제**가
아래 "결론"과 "관심 주제와의 연결"을 정한다. "프로필 없음"이면 paper-setup 스킬로 먼저 만든다.

## 흐름

### 0. 논문 특정
arXiv id 나 URL 이면 바로. 제목만 있으면 `python -m paper_analyst.resolve "<제목>"` 으로 id 를 찾고,
`확정`이 아니면 사용자에게 확인한다 — 다른 논문을 정리하는 것이 가장 비싼 실수다.

### 1. 받기·변환
```bash
python -m paper_analyst.fetch <id> --parse
```
`library/papers/<id>/meta.json` 의 `parsed.source` 를 본다. `pdf` 면 2단 논문의 줄 순서가 섞였을 수 있으니
문장이 어색한 곳은 그 이유일 수 있다고 감안한다.

### 2. 외부 신호
```bash
python -m paper_analyst.enrich <id>
```
출력된 요약만 읽는다 (`external.json` 전체를 열지 않는다). S2 는 발표 90일 미만이면 건너뛰고, 키 없이 쓰므로
429 로 실패할 수 있다 — 실패하면 다시 한 번 돌려보고, 그래도 안 되면 "S2 조회 실패"로 적고 넘어간다.

### 3. 읽기 — 절 단위로
```bash
grep -n '^#' library/papers/<id>/parsed/paper.md          # 목차와 줄 번호
```
- 초록은 `meta.json` 의 `abstract`.
- 그다음 Read 의 offset/limit 로 **서론 → 방법 → 실험(주요 표) → 결론·한계** 만 읽는다. 참고문헌과 부록은
  필요할 때만 (특정 수치·설정을 확인해야 할 때).
- `paper.pdf`·`paper.html` 은 열지 않는다 — md 보다 5~25배 크다.
- 그림은 결과를 이해하는 데 꼭 필요한 것만 `parsed/images/` 에서 연다.
- 예산: 일반 논문 본문 ≈ 7~10k 토큰. 50쪽짜리 기술 보고서는 다 읽지 말고 사용자 관심 주제에 걸리는 절을 고른다.

### 4. 웹 검색 1회
`"<짧은 이름 또는 제목>" review OR analysis OR criticism` 로 standard 검색 한 번. 결과의 상당수는 제조사 자료나
AI 요약 사이트(themoonlight, emergentmind 등)다 — 이런 건 외부 평가로 세지 않는다. **독립적인 평가가 없으면
"독립 평가 못 찾음"이라고 적는 것도 정보다.**

### 5. 외부 평가의 수치는 원문과 대조
외부 글이 논문의 수치나 발견을 인용하면 `grep` 으로 paper.md 에서 찾아 맞는지 본다. 맞으면 "본문 확인",
못 찾으면 "본문에서 못 찾음". 2차 출처가 수치를 틀리게 옮기는 일이 흔하다.

### 6. notes.md 쓰기 (공개) + notes.private.md (개인, 선택)
`library/papers/<id>/notes.md` 에 아래 양식으로. 프로필의 `reader.language` 로 쓰되 기술 용어·고유명사·수식은 원문
(양식의 절 제목도 그 언어로 옮긴다).
**notes.md 는 공개 저장소에 올라간다** — 논문 내용·평가·일반적인 적용 아이디어만 쓴다.
사용자의 회사·업무·경력·동료 이야기, 사내 시스템에 대입한 내용은 `notes.private.md` 에 쓴다 (`.gitignore` 대상).
공개본에서는 "사내 RAG" 대신 "대규모 문서 RAG"처럼 일반 표현으로 쓴다.

### 7. 보고
채팅에는 **용어와 구조 → 개요 → 결론** 순서로 + notes.md 경로 (개인 대입은 채팅에서 말하고 notes.private.md 에). 전문을 다시 붙이지 않는다.
결과부터 말하면 사용자가 "그게 무슨 구조인데?"를 되묻게 된다 — 구조를 먼저 깔고 결과를 얹는다.

## notes.md 양식

```markdown
# <제목>

- arXiv <id><버전> · 발표 <YYYY-MM-DD> · <주 카테고리> · <학회·수상 (있으면, 등급까지)>
- 변환 <html|pdf> · 읽은 범위: <읽은 절 번호/이름>
- 정리 <YYYY-MM-DD> KST

## 먼저 — 용어와 구조
<결론을 읽기 전에 알아야 할 것만: 약어 풀이, 이 논문에서 그 용어가 가리키는 구체적 구조(그림 한 장 수준),
비교 대상(기준선)이 무엇인지, 흔히 쓰는 뜻과 다르면 그 차이. 예: "MAS = 같은 모델 6개가 서로 답을 읽는 토론형 —
작업을 나눠 맡기는 서브에이전트형과 다름". 짧은 논문이면 2~3줄, 해당 없으면 생략>
(이 절이 없으면 결론이 엉뚱하게 일반화된다 — 실제로 "멀티에이전트는 비효율적"으로 오독될 뻔함)

## 결론
**<이 논문을 한두 문장으로 판정 — 무엇을 보여줬고, 어디까지 믿을 수 있나>**
- **가져갈 것:** <reader.lens 관점에서 바로 쓸 수 있는 것 — 실무 관점이면 설계·지표, 연구 관점이면 방법·열린 문제>
- **믿어도 되는 결과:** <통제가 잘 됐거나 외부에서 뒷받침된 것>
- **해석에 주의할 결과:** <저자 주장뿐이거나, 반론·통제 부족이 있는 것>
- **읽는다면:** <원문에서 볼 절만, `3.3절(…)` · `표 1(…)` 처럼 — 나머지는 이 notes 로 충분>
(결론은 맨 앞에 둔다. 논문이 쌓이면 결론 블록만 모아서 비교한다 — 편당 ≈ 400자)

## 한 줄 요약
<무엇을 했고, 무엇이 새로운가 — 한 문장>

## 문제와 핵심 아이디어
<어떤 문제를, 왜 기존 방법으로 부족했고, 무엇을 바꿨나. 3~6줄>

## 저자 주장
- <주장> — <근거: 표·그림·절 위치> 
(논문이 말한 것만. 수치는 원문 그대로, 비교 대상과 조건을 같이)
(근거 위치는 원문 번호 그대로 `6.1절` · `7.1~7.2절` · `3장` · `부록 F` · `부록 B.1` · `표 3` · `표 3·4` · `그림 2` 로 쓴다 —
화면이 이 표기를 눌러 받아 둔 원문의 그 부분을 펼친다. `Table 3`·`Sec. 6.1`·`Appendix F` 처럼 영어로 쓰면 연결되지 않는다)

## 실험에서 볼 것
<설정·기준선·평가의 특이점. 비교가 공정한지, 무엇을 안 쟀는지>

## 한계
- 논문이 밝힌 것: …
- 읽으며 본 것: … (내 판단임을 분명히)

## 외부 평가
| 출처 | 내용 | 성격 |
|---|---|---|
| <후속 논문 제목 (S2 인용 문맥)> | <그 논문이 이 논문을 어떻게 썼나> | 학계 후속 연구 |
| <HN 글, 점수·댓글 수> | <상위 댓글 요지> | 커뮤니티 |
| <블로그·기사> | <요지> | 독립 비판 / 전문가 추천 / 제조사 |
(조회했는데 없는 소스는 행을 만들지 말고 아래 한 줄에 모은다)
조회했으나 없음: <예: HN 없음, 독립 평가 못 찾음, S2 건너뜀(발표 70일)>

## 관심 주제와의 연결
<현재 프로필 interests.topics 중 실제로 닿는 것만 — 일반 표현으로. 개인 업무에 대입한 내용은 notes.private.md. 닿는 게 없으면 "직접 연결 없음".
억지로 만들지 않는다 — 사용자는 이 섹션으로 읽을 우선순위를 정한다>

## 출처
- 논문: https://arxiv.org/abs/<id>
- <외부 평가에 쓴 URL 전부>
```

## 지킬 것 (왜)

- **저자 주장과 외부 평가를 섞지 않는다.** 섞으면 사용자는 무엇이 검증된 것인지 알 수 없다.
- **외부 평가에는 출처의 성격을 단다.** 학계 후속 연구 / 독립 비판 / 전문가 추천 / 제조사 / 커뮤니티.
  제조사 자료와 AI 요약 사이트를 "평가"로 세면 실제보다 검증된 것처럼 보인다.
- **수상은 등급까지.** EMNLP 는 Best 2 · Outstanding 22 · SAC Highlight 22 — "수상작"으로 뭉뚱그리면 무게를 잘못 읽는다.
- **숫자는 출처를 붙인다.** 논문 본문 / 외부 글 인용 / 확인 안 함을 구분한다.
- **모르면 모른다고 쓴다.** 읽지 않은 절의 내용을 추측해서 채우지 않는다.

## 여러 편일 때

한 번에 여러 편을 받으면 먼저 `fetch.py` 로 모두 받고 각 초록만 읽어 (편당 ≈ 300 토큰) 표로 보여준 뒤,
사용자가 고른 것만 위 흐름으로 정리한다. 본문을 다 읽고 나서 고르면 토큰이 수 배로 든다.

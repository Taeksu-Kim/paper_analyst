# paper-find — 읽을 논문 고르기

후보는 **여러 소스의 신호로 넓게 모으고**, 고르는 것은 **초록을 읽고 실무 기준으로** 한다.
신호(upvote·스타·HN·인용)는 "사람들이 봤다"는 뜻이지 "쓸모 있다"는 뜻이 아니다 — 신호만으로 순위를 매기지 않는다.

작업 위치: 저장소 루트. 파이썬 3.11+.

## 시작 — 현재 프로필 읽기
```bash
python -m paper_analyst.profile
```
출력의 **읽는 관점·판정 기준·출력 언어**를 이번 작업 내내 따른다. "프로필 없음"이면 paper-setup 스킬로 먼저 만든다.
`개인 맥락(비공개)` 줄이 있으면 그 파일도 읽어 판정에 쓰되, lists/ 공개 목록에는 일반 표현으로만 옮긴다.

## 흐름

### 0. 기간과 목적을 먼저 고정
- 프로필의 `reader.language` 로 쓴다.
- **기간은 arXiv 발표일 기준으로 엄격히.** "올해"면 올해 발표된 논문만 — 올해 수상했어도 작년 논문은 목록에서 따로 표시한다.
- 목적: 지난 구간 따라잡기(발표 3개월 이상 지남) / 최근 동향(3개월 미만) / 특정 주제. 목적에 따라 믿을 신호가 다르다
  (`docs/SOURCES.md`): 3개월 미만은 인용이 없으니 HF·HN·스타, 지난 기간은 S2 인용이 주 신호.

### 1. 모으기 — `paper_analyst/discover.py`
```bash
python -m paper_analyst.discover --from 2026-09 --to 2026-11                  # 프로필의 discover.sources 전부
python -m paper_analyst.discover --from 2026-10 --to 2026-11 --sources hf,hn  # 최근이면 S2 빼기
```
- 화면에는 **신호 기준 통과 후보만** 나온다 (기준은 프로필 `[discover].thresholds`, 하나라도 넘으면 통과, 합산 안 함).
- 신호 `kw` = 관심 키워드(`discover.keywords` + `watch.models`) HF 검색에 걸린 것 — 인용·HN·스타가 약한 응용 논문용 별도 경로다.
  `kw` 만으로 들어온 후보는 신호가 약하다는 뜻이니 초록 판정을 더 엄격히 한다. 학회 수상작은 이 수집에 안 잡힌다 → `sources.curated` 로 따로.
  주제를 통과한 전체는 `library/candidates/<날짜>_<프로필>_<from>_<to>.jsonl`.
- S2 는 키 없이 쓰면 429 가 잦다. 로그에 `(HTTP 429)` 가 찍힌 주제는 **빠진 것**이니 결과에 그렇게 적는다.
- 신호 통과가 너무 적으면(최근 구간) jsonl 에서 `upvotes` 상위를 더 본다 — 기준을 몰래 낮추지 말고 낮춘 기준을 적는다.

### 2. 초록 읽기
신호 통과 후보와 jsonl 상위 몇 편의 초록만 읽는다 (편당 ≈ 300 토큰). HF `https://huggingface.co/api/papers/<id>` 의
`summary`, 없으면 arXiv abs. 본문은 읽지 않는다 — 본문은 paper-read 몫이다.

### 3. 프로필 기준으로 판정
편마다 프로필 `reader.criteria` 의 항목을 하나씩 짧게 (예시 — nlp 프로필: 학습 필요 여부 / 새로 얻는 것 / 관심 주제 접점 / 재현 수단).
`reader.lens` 가 우선순위를 정한다 (예: 실무 관점이면 확인형 연구보다 새 기법).

판정: **읽기 / 보류 / 제외** + 한 줄 이유. 근거 강도도 같이 적는다 — 저자 주장뿐인지, 외부에서 뒷받침됐는지.

### 4. lists/ 에 쓰기
`lists/<날짜>_<짧은 이름>.md`:
```markdown
# <목록 이름>
> <날짜> KST. 기간 <from>~<to> (arXiv 발표일 기준). 소스 <hf,hn,s2>, 기준 <thresholds>. 실패한 소스: <없음 | s2 주제 n개 429>.
> 후보 파일: library/candidates/<파일>.jsonl

## 읽기
| arXiv | 제목 | 신호 | <criteria 항목마다 한 칸> |
## 보류 / 제외 (한 줄 이유)
## 기간 밖이지만 언급할 것 (발표일 명시)
```

### 5. 보고
채팅에는 "읽기" 표와 각 한 줄 이유, 목록 파일 경로. 다음 단계로 paper-read 할 1편을 추천한다 (이유 포함).

## 붙여넣은 목록 처리 (큐레이터·블로그·SNS)
1. 글에서 논문 제목·링크만 뽑아 `paper_analyst/resolve.py` 로 arXiv id 를 찾는다:
   ```bash
   python -m paper_analyst.resolve "제목 1" "https://arxiv.org/abs/…"   # 또는 한 줄에 하나씩 stdin
   ```
   `확정`(정규화한 제목이 정확히 같음)만 그대로 쓰고, `확인 필요`는 후보 제목을 보여 주고 사용자 확인,
   `못 찾음`은 그렇게 적는다. 비슷한 제목으로 다른 논문에 붙는 것이 가장 비싼 실수다.
2. 자동 수집 후보(jsonl)와 겹치는지 보고, **자동 수집이 놓친 것**을 따로 표시한다 — 붙여넣은 목록의 가치는 거기 있다.
3. 큐레이터 실명·개인 계정 정보는 저장 파일에 쓰지 않는다 (별칭 사용). 큐레이터 관련 목록은 `*.private.md` 로 둔다.
4. SNS 자동 수집은 하지 않는다 — 사용자가 붙여넣은 글만 다룬다.

## 지킬 것 (왜)
- **신호를 합산·가중하지 않는다.** 임의 가중치는 근거 없는 순위를 만든다. 각 신호를 그대로 보여 주고 판단은 초록으로.
- **HN 점수는 화제성이지 품질이 아니다.** HN·스타로 들어온 논문은 paper-read 에서 반복 실행 여부와 기준선부터 본다.
- **HF upvote 상위는 대형 모델 보고서가 차지한다.** 응용 논문은 upvote 20~80 구간에 있다 (`docs/SOURCES.md` 측정).
- **수상은 등급까지** (Best / Outstanding / SAC Highlight). "수상작"으로 뭉뚱그리지 않는다.
- **숫자에 출처를 붙인다** — 이번에 측정한 값인지, 문서·외부 글에서 인용한 값인지.
- 관심 주제·관심 목록은 사용자가 정한다 — 프로필에 임의로 추가하지 않는다.

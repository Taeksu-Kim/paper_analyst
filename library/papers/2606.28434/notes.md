# SWE-MeM: Learning Adaptive Memory Management for Long-Horizon Coding Agents

- arXiv 2606.28434v1 · 발표 2026-06-26 · cs.SE · EMNLP 2026 **SAC Highlight** (공식 수상 페이지 확인, 2026-11-14)
- 변환 html · 읽은 범위: Abstract, 1 Introduction, 2 Proposed Approach, 3 Experiment, 4 Further Analysis, 5.2 Memory Management, 6 Conclusion (부록·참고문헌 안 읽음)
- 정리 2026-11-14 KST

## 한 줄 요약
코딩 에이전트에게 "언제·어느 구간을·어떻게 요약할지" 스스로 정하는 압축 도구를 주고, SFT(합성 궤적·커리큘럼) + 압축을 고려한 GRPO 로 학습시켜 32K 컨텍스트에서 SWE-Bench Verified 43.4%(4B) / 60.2%(30B)를 낸다.

## 문제와 핵심 아이디어
- ReAct 식으로 이력을 계속 붙이면 로그·실패한 탐색이 쌓여 컨텍스트가 넘치거나, 넘치지 않아도 집중이 흐려진다.
- 기존 방법은 **고정 규칙**(임계치 도달 시 전체 요약, 끝난 하위작업 접기, 최근 턴 보존)이라 정보 가치가 다른 구간을 구분 못 하고,
  컨텍스트 *최대 길이*는 줄여도 *총 토큰·스텝*은 오히려 늘린다 (그림 1c).
- 해법: `compress(analysis, start_step, end_step, content, remaining_work)` 도구 — 에이전트가 구간을 골라 요약으로 바꾸고,
  남은 일을 궤적 끝에 붙인다. 요약을 다시 요약하는 점진 압축 가능. 관측마다 현재 스텝·남은 컨텍스트를 메타데이터로 알려준다.
- 학습: (1) 기반 모델이 푼 궤적에 GPT-5.1 이 "지금 압축할지"(예산 압박 + 하위작업 완료·정보 밀도 낮음·집중 저하)를 판정·인자를 합성
  → 거절 샘플링·규칙 필터(압축률 20~80% 밖, 너무 짧은 구간, 범위 불일치 마스킹) → 2단계 커리큘럼(2단계는 선제적 압축 궤적 위주).
  (2) Memory-aware GRPO: 압축 지점에서 궤적을 잘라 추론 때와 같은 압축된 앞부분에서 학습, 롤아웃 단위 손실 평균,
  스텝 단위 마스크(늦은 압축·오버플로·잘못된 도구 호출 등).

## 저자 주장
- SWE-Bench Verified, 32K 한도: 4B 43.4% (SFT 41.6%), 30B 60.2% (SFT 58.8%) — 표 1
- 같은 30B 기반 ReAct: 256K 51.6% / 32K 38.6% → SWE-MeM 32K 60.2% — 표 1
- 효율: 총 토큰 0.91M (기반 ReAct 대비 94.7%), 경쟁 방법은 96.4~203.9% — 표 2. 스텝은 123.5% (Context Folding 194.9%)
- 학습 없이 워크플로만(추론 때 GPT-5.1 이 압축 판단) 30B 58.4% — 표 1
- 절제: 선제적 → 임계치 호출 57.4%, 구간 선택 → 전체 요약 57.6% (30B) — 그림 4. 커리큘럼으로 선제적 호출 비율 2.3→16.1%(4B), 4.1→14.7%(30B)
- 압축 도구를 빼고 256K 로 돌리면 4B 43.4 → 37.6% — 4.2절 ("넘침 방지 이상으로, 깨끗한 작업 컨텍스트가 도움")
- SWE-Bench Multilingual 4B 7.3→19.0, 30B 35.3→40.7 / Pro 4B 2.6→15.2, 30B 28.9→31.7 (기반 256K vs SWE-MeM 32K) — 표 3

## 실험에서 볼 것
- **기준선 비교가 통제되지 않았다.** 경쟁 메모리 방법은 기반 모델(Qwen2.5-Coder-32B, Seed-OSS-36B)·컨텍스트(32K/64K)·스텝 한도가
  다 다르고, 표 2 의 토큰·스텝은 방법마다 한쪽만 보고된다(–). 같은 모델·같은 스캐폴드에서 다시 돌린 비교가 아니라 보고값 대조로 보인다.
  저자도 "on their respective base models" 라고 개선 폭으로 비교한다 (3.4절).
- **이득의 상당 부분이 교사 모델 판단에서 온다.** 학습 없이 GPT-5.1 판단만 붙인 Workflow-only 가 58.4%, SFT 후 58.8% — 차이 0.4%p.
  학습의 기여는 "추론 때 외부 모델 없이 같은 성능을 내게 됐다"는 데 있고, RL 이 +1.4%p.
- **차이가 작고 분산 보고가 없다.** 500문항 기준 1%p = 5문항. 절제 차이(57.4·57.6 vs 58.8)는 1~1.4%p. 읽은 범위에서
  반복 실행·신뢰구간을 보지 못했다.
- 4B 는 너무 약해서 설계 절제는 30B 만 했다고 밝힘.

## 종합
"압축을 규칙이 아니라 에이전트의 행동으로 학습시킨다"는 **방법론 논문**이다. 발표 5개월 만에 인용 24건 중 다수가
"모델이 압축을 결정하는" 계열의 대표 사례로 쓰고 있어, **문제 설정과 접근 방향은 학계에서 받아들여졌다**.
반면 "기존 메모리 방법보다 성능·효율 모두 낫다"는 주장은 **아직 저자 주장뿐** — 기준선이 다른 모델·설정의 보고값이고
차이가 1~2%p 라, 같은 조건 재비교 없이는 확정하기 어렵다. 가장 단단해 보이는 결과는 "압축 도구를 빼면 256K 로도
성능이 떨어진다"(43.4→37.6)와 "총 토큰이 기반 ReAct 보다 적다"는 것 — 둘 다 같은 모델 안에서의 비교다.

## 관심 주제와의 연결
- **context compaction / agent memory**: 직접 해당. 압축을 도구 호출로 노출하고, 관측에 "현재 스텝·남은 컨텍스트"를 넣는 설계는
  학습 없이도 가져다 쓸 수 있는 부분 (Workflow-only 가 학습 버전과 거의 같은 성능).
- **agent harness**: 같은 모델이라도 스캐폴드(압축 도구 유무)에 따라 43.4 vs 37.6 — 하네스 설계가 성능을 좌우한다는 사례.
- **LLM serving / 로컬 모델**: 4B·30B-A3B 와 32K 컨텍스트에서의 결과라 작은 로컬 모델 환경과 조건이 가깝다.

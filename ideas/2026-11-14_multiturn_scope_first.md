# 멀티턴에서 길을 잃는 문제 — 원인과 설계안

> 2026-11-14 KST · 출발점: LLMs Get Lost In Multi-Turn Conversation (2505.06120, **2025-05 논문** — 2026 목록에선 분리)
> 논문 정리: `library/papers/2505.06120/notes.md` · 수치는 논문 본문(v1)

## 편차는 두 단계로 생긴다
1. **씨앗 — 정보 부족:** 빈칸을 추측으로 채워야 해서 실행마다 다른 가정을 고른다.
2. **증폭 — 관성:** 그 가정을 담은 답을 일찍 내고 매달려서, 정보가 다 와도 회복 못 한다. 최종 편차의 크기는 이쪽이 결정.

근거 (논문 본문)
- 온도 0(사용자·모델 둘 다)에서도 멀티턴 편차 ≈ 30% (단일 턴은 2.8~6.8) — 씨앗이 토큰 하나 수준이어도 증폭된다 (표 3)
- 번역은 나눠 줘도 하락 없음 — 지금까지 받은 범위로 확정할 수 있고 나중 정보에 뒤집히지 않는 과제 (표 4)
- 같은 정보를 한 번에 주면(Concat) 95%, 잘 된 실행(P90)은 16% 만 하락 — 정보가 나뉜 것 자체는 감당 가능

## 처방 방향
| 단계 | 처방 |
|---|---|
| 씨앗 | 모를 때 판단하지 않기 (묻기 / 미루기) |
| 증폭 | 틀린 시도를 컨텍스트에서 지우기 (리셋·압축·통합 후 재시작) |

"하다가 멈춰라"는 애매하다 → **제안: 입력으로 확정할 수 있는 범위를 먼저 정하고, 그 범위로 쪼개서 진행.**
(= 원래 분해 안 되는 과제를 번역 같은 구조로 바꾸기)

## 설계안 — 범위 우선 + 상태를 대화 밖에
```
0. 입력 → [확정 요구] / [미정 요구] 목록 (구조화 출력, 코드가 보관)
1. 확정 요구로 가능한 부분만 산출 — 미정은 자리표시 + 가정을 목록에 명시
2. 새 정보 → 목록 갱신 → 영향받는 부분만 목록 기준으로 재생성 (이전 답에 덧대지 않음)
```
- 0~1 이 씨앗을, 2 가 증폭을 줄인다 (매 단계 Concat 을 재현하는 셈)
- 같은 계열: 단계 프로토콜(YAML 등)로 진행을 고정하는 상담형 에이전트 / 근거 범위만 기록하는 생성 파이프라인 / SWE-MeM `remaining_work`

한계
- 새 조건 하나가 전체 답을 바꾸는 과제(SQL "단, 작년만")는 미리 확정할 부분이 적다 → 가정을 답에 묻지 말고 목록에 꺼내 둘 것
- 범위 판단도 LLM 이 하므로 흔들릴 수 있다 → 자유 서술 말고 구조화 출력 + 코드 검사
- **논문은 이 방식을 시험하지 않았다** (모델에 전략을 일부러 안 줌) → 아직 가설

## 추가 (2026-11-15) — 초반 상태 확정 + 단계 범위 "정의"
> **초반에 상태를 확정하고, 각 단계의 범위와 완료 조건을 정의한다.** (진행을 임의로 "제한"하는 게 아니라 "정의")

- **처음 몇 턴이 지렛대** — 경로 의존성: 앞에서 한 일 위에 다음 일을 쌓으므로 초반 차이가 커진다.
  - LLMs Get Lost: 초반 잘못된 가정에서 회복 못 함, 첫·마지막 턴 과대 반영 (본문)
  - Meta-Harness 환경 스냅샷: 초반 탐색 2~4턴 낭비 제거, 이득은 "초반 잘못된 가정이 연쇄되는 과제"에서 큼 (부록 B.3)
  - SWE-MeM: 예산 바닥 전 선제 압축, 늦은 압축엔 학습 불이익 (본문)
- **제한 vs 정의** — 최대 토큰·단계로 끊으면 쓸모 있는 작업도 잘린다. 대신 정의할 것:
  이번 단계 범위(지금 정보로 확정 가능한 만큼) · 완료 기준(Terminus-KIRA 완료 체크리스트) · 남은 일(SWE-MeM `remaining_work`) ·
  너무 일찍 "다 했다" 하지 않기(LLMs Get Lost 실패 원인 1번)
- 근거 강도: 세 논문이 다른 설정에서 같은 방향 = 경험칙. "범위를 정의하면 낫다" 자체는 직접 실험 안 된 가설.
- 문서 생성 에이전트라면: 작업 전 자료 폴더 스냅샷(파일 목록·형식·크기·언어) = 초반 상태 확정.

## 실험 아이디어 (미정)
- `microsoft/lost_in_conversation` 공개 코드·데이터로 "기본" vs "범위 우선 + 목록 재생성" 비교
- 오픈 모델 로컬 실행 (API 비용 없음, 논문이 시험 안 한 모델) · 지표는 논문 그대로 P90(능력) / P90−P10(편차)
- 최신 모델에서 현상이 아직 남아 있는지부터가 결과 (논문 모델은 GPT-4.1·Claude 3.7 세대)

# 생성 에이전트 평가 — 일반 원리와 예시

> 2026-11-15 KST. 계기: 생성 에이전트를 "입출력 고정"으로 개선했는데 성과가 안 좋았던 사례 — 상세는 모름, 일반적인 원인 후보로 정리.
> 성격: 대부분 **일반 실험 방법론 + 이번에 읽은 논문들의 근거**. 논문 근거는 출처 표기, 나머지는 판단.
> 관련: `ideas/2026-11-15_harness_autoimprove_fit.md` (0장 "목적이 양·해상도·잡음을 정한다")

## 1. 입출력 고정은 출발점일 뿐 — LLM 에서 추가로 필요한 것
평가셋의 입력과 정답을 고정하는 건 일반 방법론(벤치마크의 기본형). LLM·에이전트에서는 그것만으론 부족하다.

| 일반 방법론 | LLM·에이전트에서 추가 | 근거 |
|---|---|---|
| 입력·정답 고정 | **같은 입력에도 출력이 흔들림 → N회 실행해 분포를 본다** | LLMs Get Lost (능력 P90 / 편차 P90−P10), Rethinking MAS (편차 0.6~2.1점 = 향상 크기) |
| 학습/테스트 분리 | **개선에 쓴 평가셋은 학습용이 됨 → 탐색 세트와 확인 세트 분리** | Meta-Harness TerminalBench 비판 (2607.12227, 초록) |
| 비교 조건 통일 | 모델뿐 아니라 **프롬프트·구성·실행 환경까지** (숨은 변수 많음 — 노드 제거 시 역할 프롬프트 밀림) | Rethinking MAS |
| 기준선 | **단순 기준선이 실제로 약한지 먼저 확인** (few-shot 전부, BM25, 무작위, 단일 에이전트) | Meta-Harness (ACE ≈ few-shot), Rethinking MAS (학습 ≈ 무작위) |

새 원칙이 아니라 "LLM 에이전트 연구에서 자주 깨지고, 깨지면 결론이 뒤집힌다"는 것이 논문들이 보인 것.

## 2. 고정 세트로 개선했는데 성과가 안 좋을 때 — 원인 후보
1. **지표가 품질을 못 잼** (생성 과제에서 먼저 의심) — 좋은 답이 여럿인데 정답 출력 하나와의 유사도로 채점하면 "정답처럼 쓰기"를 최적화.
   정답과 다르지만 더 좋은 답은 감점. 예: RAG 답변 평가를 유사도 점수 대신 **사실 단위 YES/NO**("들어가야 할 사실이 들어갔나")로 하면 이 문제를 피한다.
2. **실행 간 편차** — 수정 전후를 1회씩 비교하면 "좋아짐/나빠짐"의 상당수가 우연 → 잡음을 따라 수정이 쌓임.
3. **과적합** — 같은 세트로 수정·확인 반복 → 그 세트용 문구·예외 처리. 확인 세트가 없었다면 유력.
4. **적은 데이터·좁은 범위(대표성)** — 실제 입력의 다양성(자료 길이·형식·요청 유형)을 못 담음.

| 관찰 | 의심할 원인 |
|---|---|
| 고정 세트 점수↑, **새 입력**에서 나쁨 | 3, 4 |
| 고정 세트 점수↑, **사람이 보기엔** 별로 | 1 |
| 고정 세트 점수가 **들쭉날쭉** / 안 오름 | 2 (또는 1) |
| 같은 입력 N회의 점수 차가 수정 효과만큼 큼 | 2 |

**확인 순서:** 편차 측정(같은 입력 N회) → 지표가 사람 판단과 맞는지 → 확인 세트로 과적합. 앞의 둘이 틀어져 있으면 과적합 판단 자체가 불가능.

## 3. 규칙형 품질 기준의 함정 — 예시: "문서에 중복이 있으면 안 된다"
단순 규칙(유사 문장·n-gram 겹침 = 감점)은 나쁜 중복과 좋은 반복을 구분 못 한다. 그 지표로 개선을 반복하면
핵심 강조·요약까지 지워 글이 끊기는 쪽으로 최적화된다. (틀로 말하면: 반복은 정보 밀도 목적엔 잡음, 강조·흐름 목적엔 신호)

**① 나쁜 쪽을 좁게 정의** — "중복이 있나"가 아니라 "새 정보 없이 반복했나, 그 반복에 역할이 있나"
| 나쁜 중복 (잡음) | 좋은 반복 (허용) |
|---|---|
| 새 정보 없는 되풀이 | 요약·결론에서 핵심 재진술 |
| 문장·문단 복붙 | 섹션 도입부의 연결 문장 |
| 여러 섹션이 같은 내용을 나눠 가져 구조가 흐려짐 | 핵심 주제의 의도적 반복 강조 |
| 같은 사실을 다른 수치로 (→ 중복이 아니라 **불일치**, 따로 검사) | 표와 본문에서 같은 수치를 근거로 반복 |

**② 채점을 두 단계로** — 코드가 후보 탐지(유사 문장 쌍 + 위치: 같은 섹션 안 / 요약↔본문) → 판정기가 후보마다
YES/NO("새 정보 없는 되풀이인가", "요약·연결·강조 역할이 있나") → 점수는 코드. ("LLM 은 YES/NO, 점수는 코드" 구조 — 판정을 좁혀 재채점 일관성을 높인다)

**③ 검사기를 먼저 검증** — 후보 쌍 수십 개에 사람이 "나쁜 중복 / 괜찮은 반복" 라벨 → 검사기 정밀도부터 잰다.
(사후 LLM 검증기는 정밀도가 생각보다 낮을 수 있다 — 쓰기 전에 잰다)

**④ 목표가 아니라 경보로** — 0 을 만드는 최적화 대상으로 쓰지 말고 임계값 초과 문서만 표시, 줄였을 때 흐름이 망가지지 않았는지 사람이 표본 확인.
지표 하나를 끝까지 최적화하면 그 지표가 재려던 품질에서 멀어진다.

같은 함정이 생기기 쉬운 다른 규칙: "문장은 짧게", "전문 용어 금지", "모든 주장에 출처" (요약 문장·상식 문장까지 출처 요구),
"표는 N행 이하" — 전부 ①~④ 순서로 다루면 된다.

## 4. 한 줄 정리
**입출력 고정은 출발점. 생성 과제는 (1) 여러 번 돌려 편차보다 큰 차이만 믿고, (2) 지표가 정답 닮기가 아니라 품질을 재는지 사람 라벨로 확인하고,
(3) 규칙형 기준은 나쁜 쪽을 좁게 정의해 탐지(코드)와 판정(YES/NO)을 나눈 뒤 경보로 쓰고, (4) 확인 세트로 과적합을 본다.**

## 무엇이 문제였나
- v1은 기능·순서는 고쳤지만 시각 체계를 옛 화면에서 그대로 물려받았다: 아이콘 0, 모든 묶음을 테두리 상자로, 굵기 5종(800), 첫 화면 글자 2,472자 [측정, 2026-11-20, CRAFT_JS].
- 원인(스킬): 재디자인 경로가 없어 "기존 것을 따른다"가 시각 체계까지 적용됨 / 레퍼런스를 저장소 안에서만 봄 / 기술 점검 통과를 완료로 봄 / 자기 평가.
- 레퍼런스를 고치며 두 번 더 틀림: "열린다"(부품 데모)로, 다음엔 "비슷한 서비스"로 고름 → 사용자: "전문 디자인으로서 좋은 걸 보고, 컨셉은 그때그때 맞추고".

## 어떻게 고쳤나
- 수준 레퍼런스(토스·당근·GitHub 실제 화면 + 디자인 시스템 문서), 기능 레퍼런스(같은 과업 제품 → 필요한 기능만), 일관성(저장소 안)으로 역할을 나눔.

## 5. 결론 강조와 색 (사용자: "형광펜보단 볼드가 낫지 않나", "색조합이 좀 마음에 안 드는데", "스킬이 컬러를 다루는 방식도 고도화가 필요하지 않나")
- 결론 강조: 형광펜 → 굵기 (첫 문장 600·본문색, 나머지 보조색).
- 첫 색 후보 3개(`palettes/`)는 대표색 hex만 바꿔 셸 말고 구분이 안 됐다 → 스킬에 색 체계 방식을 넣음 (ui-design `topics/color.md`, `scripts/palette.py`).
- 원인 [측정, OKLCH]: 바탕 크림 H≈99 · 글자 회색 H≈150 · 초록 H≈171 — 세 계열이 따로 놂. 토스 회색은 토스 파랑 계열(H 248~258)로, 당근 회색은 차가운 중립.
  크림 바탕 + 세리프 제목은 알려진 AI 기본값 1번이었다.
- 새 방식 후보 3개(`palettes-v2/compare-paper.png`): A 초록 물든 회색 + 초록 책등 / **B 차가운 중립 + 밝은 책등 (사용자 선택)** / C 흑연 책등 + 잉크 파랑.
- 비교 시트 두 장은 정리하다 실수로 지워 **다시 그렸다**: 첫 칸은 당시 실제 캡처(`4-v3-after-review-paper.png`), 후보 칸은 같은 후보 색을 최종 코드 위에 덧씌운 것이라 제목 글꼴(산세리프)·로고 타일이 당시와 다르다.
- 적용: `5-v3-palette-B-paper.png`. 바탕·지면이 화면의 71% [측정 `palette.py area`], 초록은 현재 위치·주 버튼·결론 라벨에만.

## 6. 마지막 평가 회차 (가치·구조 2회 중 2회차)
- 조건 모르는 평가자: v1 "아마추어 쪽" / 현재 "가깝다". 결정적 이유: 본문 중심 위계, 역할별 컨트롤 무게, 렌더링 결함·기본 컨트롤 없음.
- 디테일 반영: 선택 행 막대를 카드 안으로, 도구줄 이중 구분선 → 한 줄, arXiv 밑줄을 글자에 붙임, 대화 머리 높이 맞춤, 세션 칩 중립색,
  도구 단계는 조용한 회색 체크(평가자 1은 "완료 반복이 잡음", 평가자 2는 "상태가 없다" — 사이), 태그 줄 페이드, 근거 줄은 "읽은 범위"부터.
- 최종 캡처 `6-final-paper.png`. browser_check 147/147, pytest 13/13.
- 다음 후보 (평가자 ③ 빠진 기능, 이번 범위 밖): notes 직접 편집, 원문 열기 버튼, 목록 정렬, 긴 notes 목차, 대화 결과의 파일 경로 → "노트 보기" 링크.
  → 2026-11-21 모두 넣음 (브랜치 `feat/reader-tools`): notes 편집(불러온 때 수정 시각으로 충돌 확인, 409면 덮어쓰지 않음), 메타 줄 "PDF 원문",
  검색 옆 정렬(정리순·발표일순·제목순, 기억), 절 3개 이상이면 접힌 목차, 대화의 notes 경로 → "노트 보기". browser_check 155/155, pytest 14/14.
- 판단 남김: 책등 맨 위 초록 앱 타일(평가자 "이름 없는 로고 타일은 생성 기본값"), 세리프 제목(세 평가자 중 둘이 "에디토리얼 기본 조합"), 결론 뒷문장 크기.

## 7. 남은 판단 정리 (사용자: "니 추천대로 진행")
- 책등 맨 위 채운 초록 로고 타일 → 아이콘만 (평가자 "이름 없는 로고 타일은 생성 기본값").
- 논문 제목 세리프(Newsreader) → Pretendard 600. 크림 바탕을 바꾼 뒤에도 "에디토리얼 기본 조합" 지적이 남아, 앞서 정한 순서(바탕 먼저 → 그래도 걸리면 세리프)대로.
  웹 글꼴은 Pretendard 한 벌만.
- 후보함 제목 앞 글자 기호 `▸`·`▾` → 선 아이콘 (펼치면 회전). 행마다 채운 버튼은 키보드로 고른 행 하나뿐이라 그대로.
- 최종 캡처 `7-final-paper.png`. browser_check 147/147, pytest 13/13.

## 이번에 배운 것
- 스킬 기준 문구가 실패를 만들 수 있다: "아이콘을 내비·행동·상태·**메타 앞에**"라고 적어 두자 메타마다 아이콘을 붙였고, 평가자가 "장식 아이콘 남발 — AI 기본 패턴"으로 짚었다 → 스킬 문구를 고침 (ui-design NOTES D17).
- 시안을 실제 데이터로 옮기면 시안에서 안 보이던 실패가 나온다: 실제 결론은 4줄이라 형광펜이 문단 전체를 덮었고, 실제 notes의 긴 인라인 코드가 고정폭 줄로 보였다.

## 남은 문제
- 평가자끼리 갈린 것: 가운데 지면을 떠 있는 흰 카드로 둔 것 — 시안 평가자는 강점, 구현 평가자는 "앱 틀 안에 카드를 띄우는 AI 기본 구성". 지금은 유지 (사용자 판단 필요).
- 같은 지적 두 번: "베이지 바탕 + 세리프 제목 + 진녹색 + 세로 레일"이 요즘 AI 미감에 가깝다 (시안·구현 평가자 모두). 스킬 C2에 기록.
- 후보함: 행마다 채운 "읽을 것" 버튼(주 동작이 여러 개), 제목 앞 `▸` 글자 기호 — 이번 범위(논문 상세) 밖.
- notes 본문의 영문 뒤 조사 띄어쓰기("LLM 을")는 정리 스킬(paper-read)이 쓴 글 — 화면이 아니라 글쓰기 쪽 문제.

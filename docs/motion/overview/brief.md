## 사실 (옮기기만)
단계·주체 (README 순서):
1. 후보 찾기 — "논문 후보를 찾고(HF·HN·Semantic Scholar)" / discover: "HF·HN·S2 수집 → 기간·주제·신호 필터"
0. 사람 요청 — "대화창에서 "10~11월 에이전트 논문 후보 찾아줘""
2. 사람 판정 — "후보함에서 읽을 것·보류·제외" / 정리 시작도 사람: "논문을 열고 "Claude 에게 정리 시키기""
3. 받기·변환 — "받아서 마크다운으로 바꾼 뒤" / "PDF 를 Claude 에 직접 넣지 않는다 — 변환된 md 만 절 단위로 읽는다 (토큰)"
4. 외부 평가 — enrich: "외부 신호(S2 인용 문맥·HN·PWC·HF) → external.json" / Semantic Scholar: "다른 논문이 이 논문을 인용한 문장"
4-1. 웹 글 — "웹 검색(블로그·비판 글)은 하지 않음 — 읽는 쪽(Claude)이 논문당 1회"
   제약: "**발표 90일 미만 논문은 S2 를 조회하지 않는다** (인용이 아직 없음 — 호출·429 만 늘림)"
5. Claude 정리 — "**Claude(Claude Code)가 읽고 정리**한다" / "정리가 끝나면 서재에 결론이 쌓인다"
6. 결론 카드 — "논문 한 편 = 결론 카드 한 장" / 카드: "결론 → 가져갈 것 → 믿어도 되는 결과 / 해석에 주의할 결과"
7. 비교 — "담은 논문들의 결론을 항목별로 나란히"
8. 발행 — 초안은 paper-post 스킬: "notes·ideas → LinkedIn·블로그 초안" / "초안을 LinkedIn 글자 / 블로그 마크다운 / 티스토리 HTML 로" / "**게시는 사람이 누를 때만.**"
오가는 것: 후보(제목·신호) → 논문 md(절) + 외부 평가(인용 문장·HN 글) → notes.md(결론 카드) → 초안

## 강조
제목 (결론 문장): 논문을 찾아 읽고, 외부 평가를 붙여 실무 결론 카드로 (README h1 "논문을 찾아 읽고, 외부 평가를 붙여 실무 관점의 결론을 낸다")
결론 층 —
- 가장 큰 모양: **결론 카드 한 장** (근거: "논문 한 편 = 결론 카드 한 장") — 흐름이 끝에 만들어 내는 결과. 칸 이름만: 결론 / 가져갈 것 / 믿어도 되는 결과 / 해석에 주의할 결과
- 큰 값: 없음 — 890 → 12 는 과정 층 위쪽(결론 카드보다 작게, 피드에서 읽히는 크기). 근거: 첫 독자 리뷰 "숫자가 카드와 시선을 다툰다"
과정 층 — 단계 이름, 출처 이름(약어 없이), 사람 줄의 네 이름표
누가·어디서 (compose §1): 왼쪽 좁은 "사람" 줄 / 오른쪽 넓은 "도구·Claude" 길. 사람 줄의 이름표는 할 일을 글로 (같은 손 아이콘 반복 안 함):
  "찾아 달라고 요청" (후보 모으기 높이) · "읽을 것 고르기" (12 → 서재 높이) · "정리 시키기" (받기 높이 — README: 받기·외부 신호·웹 검색은 paper-read 안, 정리 시킨 뒤) · "확인 창에서 게시" (발행 높이)
성질 → 모양:
| 단계 | 성질 (글 그대로) | 말 그대로의 모양 |
|---|---|---|
| 후보 모으기 | 수집 → 필터 | Hugging Face·Hacker News 두 이름에서 점들이 모여 "890" → 같은 자리에서 빠지며 "12". 옆 이름표 "신호 통과 · 2026-10~11 실측" |
| 받기·변환 | PDF 를 직접 넣지 않고 md 를 절 단위로 | 논문 한 장이 절 칸으로 나뉘고, 그중 일부 칸만 아래로 이어지는 선. 이름표 "마크다운 절 단위 — 필요한 절만" |
| 외부 평가 | 바깥 글을 같은 논문에 붙임 | 바깥 이름표(인용한 논문의 문장 · Hacker News 글·댓글 · Papers with Code·HF 추천)에서 선이 **논문**에 와 붙음 |

| 잘못 믿을 것 | 막는 요소 |

## 화면 묘사 (첫 독자 리뷰어용)
끝 화면: 맨 위 제목 "논문을 찾아 읽고, 외부 평가를 붙여 실무 결론 카드로". 왼쪽에 좁은 "사람" 세로 줄, 오른쪽에 위에서 아래로 이어진 넓은 길.
길 맨 위: "Hugging Face"·"Hacker News" 두 이름에서 점들이 모여 "890편"이 되고 줄어 "12편"(옆에 "신호 통과 · 2026-10~11 실측"). 12편에서 한 편이 "서재 · 읽을 것"으로 간다.
그 아래 논문 한 장이 절 칸으로 나뉘고 일부 칸만 아래로 선이 이어진다("필요한 절만"). 오른쪽 바깥의 "인용한 논문의 문장(발표 90일 뒤)"·"Hacker News 글·댓글"·"Papers with Code·HF 추천"에서 온 선이 이 논문에 붙는다.
논문에서 선이 "Claude" 칸으로 가고 옆에서 "웹 글 1회 검색"도 들어간다. 그 아래 화면에서 가장 큰 결론 카드 한 장(결론 / 가져갈 것 / 믿어도 되는 결과 / 해석에 주의할 결과).
카드 아래 두 줄: "비교 — 카드끼리 같은 칸 나란히", "발행 — Claude 초안 → 확인 창 → LinkedIn (블로그는 복사)".
왼쪽 사람 줄에는 각 높이에 "찾아 달라고 요청", "읽을 것 고르기", "정리 시키기", "확인 창에서 게시"가 있고 오른쪽 길과 짧은 선으로 이어진다.
움직임: "찾아 달라고 요청"이 켜지고 점들이 모여 890편, 빠지며 12편. "읽을 것 고르기"가 켜지면 12편에서 한 편이 "서재 · 읽을 것"으로 간다.
"정리 시키기"가 켜지면 그 논문이 받아져 절로 나뉘고, 바깥 평가 선이 붙고, 일부 절과 평가가 Claude 칸으로 이어지며 웹 글 1회 검색도 들어간다.
닿는 순간 결론 카드가 커지며 나타난다. 마지막에 비교·발행 줄이 그려지고 "확인 창에서 게시"가 켜진다.
